# Fiteatsy — User and Practitioner Value Model

## 1. User Value

The user should receive a coherent health-management experience from information that would otherwise remain fragmented across devices, apps, reports and memory.

### User Questions Fiteatsy Should Help Answer

- What has changed in my health recently?
- Am I improving over time?
- Which health indicators need attention?
- How do my latest reports compare with previous reports?
- What does my recent wearable/health data show?
- What medicines do I need to remember?
- What intervention/plan am I currently following?
- Is my progress moving in the intended direction?
- What should I discuss with my practitioner?

## 2. Practitioner Value

The practitioner should receive a longitudinal, authorised view rather than relying only on periodic consultations or user recollection.

### Practitioner Questions

- What is the client's latest available health context?
- When was the data last synchronised?
- Which metrics have materially changed?
- Which biomarkers are improving or deteriorating?
- What does the report history show?
- How is the client progressing under the current intervention?
- Does the nutrition/recovery plan need modification?
- Which clients require review?

## 4. Trust Requirements

Both user and practitioner experiences depend on:

- correct identity;
- data provenance;
- freshness;
- privacy;
- authorised access;
- longitudinal consistency;
- understandable calculations;
- clear distinction between measured fact and generated explanation.

## 5. Product Success Direction

Success should not be reduced to app opens or notification clicks.

Product outcomes should eventually consider measures such as:

- sustained health-data continuity;
- report-history completeness;
- practitioner review effectiveness;
- intervention adherence where appropriate;
- measurable progress in governed health indicators;
- successful identification of deterioration requiring review;
- user understanding and engagement with their health history.

Exact clinical/product KPIs require separate approval.
